# Graph-shape and prior-art audit

The hypothesis was that native batch8/width8 might pay for128 target tokens while using72, leaving room for extra tree branches. Executing the installed graph candidate-builder with CPU-only stand-ins rejects that inference for the main uniform full-batch shapes:

| Batch / native draft width | Required target tokens | Available exact FULL candidate |
|---|---:|---:|
| 8 / 8 | 72 | 72 |
| 64 / 3 | 256 | 256 |

The v2 runner passes `varlen_decode=False` when adaptive verification is disabled. The builder rounds configured sizes up to whole uniform request blocks and excludes sizes above the maximum request count. Thus configured powers of two do not imply the suspected full-batch padding. This is a **source-level candidate-construction audit**, not an observation of actual dispatch frequencies. Tails, prefill and variable verification may still pad; padding also does not make arbitrary extra attention/tree work free. Do not launch a tree integration on this unverified cost assumption.

## Relevant primary literature and implementation evidence

- [Sequoia](https://arxiv.org/abs/2402.12374): optimized tree structure and hardware-aware size/depth selection. Hardware-aware tree sizing is established.
- [Bastion](https://arxiv.org/abs/2605.29727): parallel block-diffusion trees, path-confidence surrogate, online latency estimation, and marginal-cost stopping. This overlaps directly with confidence/cost-based tree expansion.
- [UBTree](https://arxiv.org/abs/2609.39972): unigram proposal plus bigram selector and tree-oriented training. Conditional candidate transitions for tree drafting are established.
- [NVIDIA TensorRT Edge-LLM documentation](https://nvidia.github.io/TensorRT-Edge-LLM/user_guide/examples/speculative-decoding.html): DFlash2 DDTree uses parent-conditioned tree proposals when draft top-k exceeds1. Merely extending DFlash2's candidate path into a conditional tree is not a defensible broad novelty claim.
- [PolyGraph](https://arxiv.org/abs/2610.23861): GPU plan buffers avoid padded work in a custom-kernel prototype. Its scope is synthetic traces, not a complete production serving result.
- [SpecPilot](https://arxiv.org/abs/2611.02501): deployment-specific speculative-decoding algorithm/system optimization with output-token checks. Reported results are the authors', not reproduced here.

No research run or W&B throughput result was generated by this audit. Report PDF unchanged. The requested10% method improvement remains unproven.
